# Delivery roadmap

The target remains **full complete version1**. This roadmap is dependency-based,
as of 5 October 2026; it makes no unmeasured runtime estimates or new deadline
promises. Historical milestone dates in [the legacy plan](legacy-plan.md) are
background. The
[delivery ledger](version1.md) is the requirement-by-requirement authority.

## Current position

Source implementations span perception, scene assembly, retargeting, training,
rollout, diagnostics, campaign and submission. Recent source work added observed
TSDF surfaces, bounded point accumulation, mesh comparison coverage, selected-frame
hand preview, bone-preserving hand completion and exact packed-output admission.
None establishes end-to-end operation. Required optional runtimes, licensed/model
assets and runtime evidence remain outstanding. The referenced coursework sources
are present as of 2026-10-11 and remain unexecuted.

Current authorization permits implementation and documentation only. All future
execution milestones below are blocked on a changed instruction and the concrete
prerequisites for that operation. They are not requests to run checks now.

## Milestones and exit evidence

|---|---|---|

| Reconstruction comparison | Hull and optional TSDF on available public scan references | Authorized diagnostic coverage and candidate/baseline results; unavailable spoon reference stays unscored |

| Learning and optimization experiments | Opt-in PyTorch/CUDA paths, model baselines, ensembles and bounded tuning plans | Separate execution/compilation approval, owned model integration and development-only comparison evidence; no performance claim from source alone |

The scratch-depth branch remains part of the user's project scope even if it is
not the selected production depth source. A resting pilot or valid package does
not eliminate remaining tracked, scratch or delivery requirements.

## Work possible under the current instruction

Continue source-level implementation when a concrete gap is identified, keeping
changes within the feature and its consumers. Maintain documentation, dependency
proposals and explicit request drafts. Review pinned source as text. Do not
collect runtime evidence, import project modules, resolve dependencies or launch
notebooks to turn an unknown into a result.

Documentation now supplies the cross-feature map that previously unreadable
pages lacked. Future edits should keep the [artifact contracts](artifact-contracts.md)
and feature READMEs synchronized, particularly when adding metadata admission or
changing a boundary's failure policy.

## Decisions needed before execution can progress

- An explicit change to the no-testing/no-execution direction, scoped to the
  proposed work; the version 1 objective alone does not provide it.
- Concrete optional backend/package/source/weight proposals and licensed assets.
  The existing MoGe2 approval does not extend to them.
- A reviewed spoon frame convention or authoritative organiser clarification.
- Source hashes of the present coursework files in future authorized run records,
  without notebook execution.
- Explicit per-episode mass/support choices, producer paths, template selection
  and policy budgets; null request fields are not default approvals.
- Release repository/access setup and, eventually, authorization for the exact
  files to upload after preparation is complete.

No question in this list requires stopping otherwise authorized documentation or
source work. The [risk register](risks-and-open-questions.md) records why each
unresolved item matters and where a future answer belongs.

## Completion accounting

Close a ledger row only with evidence at that row's scope. Keep source changes,
historical foundation results, newly authorized operations, diagnostic scores
and external acceptance separate. Record episode coverage as well as aggregate
results, and record null/unavailable quantities explicitly. Never convert an
unmeasured resource estimate, a successful process exit or a selected preview
into a claim of full version 1 completion.
