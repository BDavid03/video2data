## Blackwell, dependency and downloader defects

The pinned Grounding DINO, SAM2, MoGe, FoundationPose, WiLoR, HaMeR and DROID Dockerfiles all start at `pytorch/pytorch:2.5.1-cuda12.4-cudnn9-devel`. Grounding DINO, FoundationPose and DROID explicitly restrict CUDA architectures to older GPUs. FoundationPose/DROID use `8.0 8.6 8.9 9.0`; Grounding DINO adds 7.0/7.5. **None includes 12.0 or PTX in these lists.** Rebuilding the same recipe does not establish Blackwell compatibility. See the [pinned Dockerfiles directory](https://github.com/nvidia-isaac/video_to_data/tree/43a3f5b4d479581f2e8bdf5e6ed7ca361d39ec5a/reconstruction/modules).

- FoundationPose hardcodes kaolin **0.18.0** from torch2.5.1/cu124 wheels; clones PyTorch3D and nvdiffrast without source pins; compiles `mycpp` and BundleSDF `mycuda`. PyTorch3D, nvdiffrast, Kaolin, Warp and custom kernels require independent checks. Model-based operation may avoid some model-free components, but vendored unconditional imports must be audited before removing them. Do not assume upstream's newer standalone installation advice already applies to the vendored copy.
- DROID hardcodes a torch-scatter cu124 wheel URL and compiles lietorch plus droid_backends with the older architecture list. Its recursive source/submodules must be pinned together. Changing an environment variable alone may not override build scripts' explicit architecture flags.
- Grounding DINO uses transformers **4.27.4** and a CUDA extension; legacy source may need an explicit compatibility patch against torch2.7 C++ APIs. Patch provenance and a real detector test are required.
- SAM2 official requirements are Python>=3.10, torch>=2.5.1, torchvision>=0.20.1. Its optional CUDA postprocessing can be unavailable with limited functionality, but any omission must be recorded. NVIDIA's low-memory wrapper uses bfloat16 and CPU offload mechanisms; neither is a measured peak-VRAM guarantee.
- Hand containers require numpy<2, smplx, manotorch, chumpy, rendering/EGL and further packages. Python3.14 is not a validated replacement for their intended Python environment. Older checkpoint loading code may hit PyTorch2.6+'s changed `torch.load` behavior; only explicitly trusted, hashed artifacts should receive narrowly scoped compatibility changes.
- WiLoR's default downloader constructs a pipeline, potentially allocates GPU memory, and automatically downloads `MANO_RIGHT.pkl` from a mirror if missing. Never use it for a metadata-only audit or before license/provenance checks. Stage the legitimately supplied MANO file in every required consumer layout, then enforce offline loading. The [pinned WiLoR-mini loader](https://github.com/warmshao/WiLoR-mini/blob/ebec42f94c389070cdd7dda6fd1bf0b4a659c960/wilor_mini/pipelines/wilor_hand_pose3d_estimation_pipeline.py) confirms the automatic downloads.
- The wrapper's host pipeline imports optional module wrappers at module import time. Even when no optional container is built, lightweight wrappers may still be required unless imports are made lazy. Do not equate skipping a model with blindly omitting every Python wrapper.
- `hamer_mesh` downloader still calls common AnyCalib downloads and optional GeoCalib/gsplat downloads. The build script builds SAM3D and other unneeded containers. Both scripts exceed the proposed minimum; use an explicit allowlist.

## Memory evidence and admission plan

Only DROID publishes an explicit minimum in the examined primary documentation: **at least 11G** for demos; **24G** for training and certain evaluations. Its source says some EuRoC/TUM evaluation fits a1080Ti while TartanAir/ETH3D require24G. These are upstream task-specific statements, not an RTX5080 guarantee. [DROID primary README](https://github.com/princeton-vl/DROID-SLAM#requirements).

No reproducible peak total-device VRAM figure for this exact Pan_Solo route was found in the examined official Grounding DINO, SAM2, MoGe2, FoundationPose, WiLoR or HaMeR documentation. Checkpoint bytes, parameter counts, A100 throughput, or the label “low memory” must not be converted into a fabricated VRAM requirement. FoundationPose registration hypotheses, video caches, full-resolution depth, hand rendering, and DROID's sequence buffer can dominate peak usage.

After approval and successful builds, run one GPU stage at a time on a short development episode segment. Start batch1, cache each stage and unload the process before the next. Use the actual calibration/orientation decisions and transformed intrinsics; preserve every frame mapping. Record total device memory (including desktop/driver/renderer), host RAM, elapsed time and disk growth. Target roughly2GiB free headroom, with admission determined from measurements. Then test FoundationPose initialization/tracking, actual MANO hands, and camera motion; inspect start/contact/release/end overlays and finite consistent transforms. Only the combined validated artifact earns “reconstruction completed.”

## Deferred choices

Known stereo calibration can eventually replace inferred geometry if allowed by the contract and validated geometrically, but this requires implementation. AnyCalib/GeoCalib/gravity are not automatically redundant: the calibrated preprocessing/world-orientation adapter must supply their needed information. The proposed minimal learned models exclude them initially while that adapter is resolved. SAM3D, DynHaMR/BMC, mesh generation, and gsplat are deferred until a demonstrated failure requires them.
